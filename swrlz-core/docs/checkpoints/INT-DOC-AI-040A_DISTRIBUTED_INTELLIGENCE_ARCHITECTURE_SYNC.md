## What this checkpoint records

The architecture document consolidates the intended direction for:

- CLIENT domain sovereignty over Android/SWRLZ knowledge and local device execution;
- SERVER heavyweight general reasoning, SWRLIE inference, online research, heavy analysis, GitHub/Forge network work, model lifecycle, and multi-node coordination;
- explicit `SWRLZ LOCAL`, `SWRLZ LAN`, `SWRLZ ONLINE`, and degraded operating states;
- SERVER-only open-ended web research, while retaining narrowly scoped CLIENT bootstrap/recovery/update/SERVER protocols where intentionally designed;
- task-scoped CLIENT-to-SERVER context disclosure and mutual validation;
- a lightweight, event-driven, game-like CLIENT architecture without a permanent high-frequency loop;
- SERVER Chat parity through shared Chat contracts/components with role-specific capabilities;
- reuse/generalization of the existing CLIENT Missions device/app/screen context as a future shared SWRLZ Context Contract;
- a model-independent Reasoning Gateway and deterministic no-model fallback;
- the first-party reasoning-provider identity `SWRLIE`, with underlying model/runtime/lineage kept explicit and replaceable;
- independent CLIENT, SERVER, and MODEL version/product lines;
- large model weights outside ordinary CLIENT/SERVER source/APK lifecycle;
- a persistent Model Vault, verification/signing/trust classes, rollback, and node-owned model storage direction;
- authenticated NODE_HOST/game-PC hosting and CLIENT administration boundaries;
- CLIENT-approved / SERVER-validated-and-executed Forge direction, including temporary transaction staging and provenance;
- separation of conversation history, operational telemetry, and curated training records;
- usage-driven SWRLIE tuning and future progression from teacher/crutch models toward increasingly SWRLZ-native reasoners.
